## 1. 当前阶段

- **阶段 0（契约与回放台架）：修正后可用。** 新修订会同时保存完整 `PerceptState`、本轮耗时和配置快照，按 `applied_sequence` 冻结回放；事件保留 actor / relationship / session 作用域。旧数据库里缺少这些快照的历史会明确报“不可验证”，不会拿当前词表伪装成过去的结果。
- **阶段 1（VA 垂直切片）：已实现。** 事件→确定性感知→纯 reducer→Russell 效价—唤醒→表达约束→trace 已接通；v4 用 `tanh` 信号和单轮融合上限把事件拉向有界目标，不再用冲量反复累加到边界。EAS、依恋和自我表征仍只读。依恋四型不再硬编码 0.5，调用者必须提供经过校准的阈值。
- **阶段 2（CAPS 行为层）：只有候选骨架，未通过阶段门禁。** 意图、调节、硬门控和 if-then 合同已实现；48 个手写样例只叫 bootstrap 合同检查，不再称为人格稳定性或反事实证明。`prompt/persona 基线消融`、独立留出集、真正的最小配对反事实、人工盲评和跨模型复测仍未完成。
- **阶段 3（桌面 / QQ 接入）：实验接入已完成，不等于阶段验收完成。** 两端的用户回复以及桌面主动发言都能 preview→注入约束→生成→commit，情绪可联动 TTS / 表情 / 桌宠；但阶段 2 尚未过门禁，因此阶段 3 只按实验接入描述。

没有落地 LoRA、模型微调、persona vector 或阶段 4 慢学习。

## 2. 2026.8.22 审计修正

| 原问题 | 修正 |
|---|---|
| preview 后经过一次 LLM 调用再提交，过期的 `precomputed` 会覆盖新状态 | preview 记录基准 revision；提交时按最新状态重算并校验预览内容。桌面和 QQ 的一整轮预览—生成—提交也已串行化 |
| 回放按 `stream_id` 排序，并用当前词表重新感知过去 | 按实际 `applied_sequence` 回放；冻结完整感知、配置和 elapsed；未提交的孤儿事件不进入投影，缺事件的孤儿 revision 会明确计为不一致 |
| 只有公开入口检查事件，底层提交可写出无原始事件的 revision；同一 `event_id` 换载荷也可能被当成幂等 | 最终 `BEGIN IMMEDIATE` 事务再次核对事件存在、流序号和不可变语义，reducer 只读取账本还原的权威事件；新库再用外键兜底 |
| 正确事件仍可搭配另一事件的 `PerceptState` 提交，之后冻结回放还会稳定复现这份错配 | v0 仅在尚无 revision 的首次投影中，用权威事件和当前配置重算确定性感知；除解析时间外必须与调用方感知一致。已有 revision 直接按冻结结果幂等返回，不受后来配置升级影响 |
| 重试可用不同 `outcome` 覆盖同一事件的既有结果，tuple / 空字典的 JSON 语义不稳定 | outcome 统一按 JSON 可还原值比较；第一个非 NULL 结果生效，已有结果只能做相同值重试，空字典也是有效结果 |
| 事件表丢掉 actor / relationship / session | 补列并带兼容迁移，新增回归测试 |
| 本轮 CAPS 已算出，却用上一轮 CAPS 选意图；调节函数完全不读 CAPS | 意图、调节和工作自我都读取本轮更新后的 CAPS；调节支持 `state_weights` |
| CAPS 的 baseline / input weight 同时以配置和旧状态为真值 | 静态参数只从本轮配置读取，状态只承载 activation；冻结回放仍使用当时配置 |
| 自伤求助、现实危险、用户说“别烦我”、攻击澄音全塞进 `threat_or_harm` | 拆成安全风险、`assistant_directed_attack`、`user_boundary` 三类瞬时情境；另加显式 `surprise_cue`，不增加人格理论轴 |
| 辱骂澄音被强制走 care，surprised 还会抢在 angry 前 | 安全风险→care，直接攻击→assert_boundary / angry，用户要求停止→withdraw / neutral；惊讶必须有语义线索 |
| 给 LLM 的约束只有“意图标签 + 固定句”，没有内核情绪和强度 | 注入 emotion、强度、立场和按语境可选的表达动作；设限允许短句制止、纠正、冷淡结束或克制反问，但禁止辱骂和威胁 |
| 重叠词条会重复计分，“谢谢”和“谢谢你”同时命中 | 改为最长非重叠匹配；语义特征在 `PerceptItem` 中标为 inferred，不再冒充 observed |
| 配置只检查少量 range，错误引用和重复 ID 可直接启动 | 增加重复 ID、枚举、默认值、CAPS / 特征 / 意图 / 调节 / 签名引用和 emotion catch-all 顺序校验 |
| `planner`、`care_skill` 路由只在调试页展示，生产链从不消费；阶段 4 `ChangeProposal` 提前占位 | 按 YAGNI 删除这两段未接入骨架，也删掉 `genesis_mode / qq_db_path / readonly` 等无消费者配置 |
| 客户端人格胶囊把 VA delta 标成绝对 valence / arousal | 改为显示 preview 后的绝对 VA 状态 |

## 3. 2026.8.22 连贯性修正（v4）

- VA 从“恢复值 + 本轮冲量”改为有界 target fusion：先按真实时间恢复，再把本轮信号融合到上下界之间的目标；清晰的夸奖仍可触发开心，普通互动和任务请求不会靠重复轮数堆到极值。
- CAPS 没有按用户复制整套人格。只有 `u_expect_user_kind` 是 `relationship` scope：配置中保留基线模板，运行时按 `relationship_ref` 克隆当前关系记录；每个克隆保存自己的 `updated_at`，因此关系 A 的冷静时间不会被关系 B 的消息改写。VA 与其余 CAPS 仍是所在物理库的全局状态。
- 直接攻击降低当前关系的友善预期；高精度道歉线索派生 `repair_attempt`，由独立的 `acknowledge_repair` 意图接住。伤害尚未恢复时，表达约束要求承认道歉但不立即说“没事”或“已经完全原谅”；没有增加“原谅值”或亲密关系状态机。
- “你是不是喜欢我”“我们是什么关系”等关系确认问题会得到当轮克制约束：只依据当前感受和已有互动证据回答，不自动许诺稳定爱情、排他关系或永久陪伴。这是表达门控，不是已经落地的亲密关系内核。
- 感知层只增加了少量高精度规则：区分直接称呼 / 命令 / 针对澄音的动作与第三方叙述，并处理“我不焦虑”一类有限否定。复杂引用、反讽、隐含指代仍不宣称已解决。
- 桌面和 QQ 都把当轮人格约束合并进唯一的顶层人设 `system` 消息；约束不会作为额外历史消息写回对话，避免历史越长时重复堆叠旧约束。工具代理与直接模型回退共用同一份当轮顶层人设。
- 桌面、QQ 与主动聊天会在 commit 和记忆写入前检查最终回复；空正文、未执行的结构化工具调用、原始 / 裸 JSON 工具调用和 Agent 提前停止文案都不会污染人格账本或聊天记忆。QQ 的异常提示路径也已修正，不会因 `chat_reply` 未赋值再次崩溃。
- 连续对话脚本改为可控的近生产台架：默认复用 Tool Agent 协议、使用显式叙事 / 固定秒数时间轴、记录真实历史窗口和已执行工具；失败轮只保留 preview 供排查，不提交状态或记忆。每次运行使用独立临时数据库，报告写入 `results/`，不再覆盖 15 号历史基线。

这些修正处理的是已发现的工程错误和表达连续性，不改变阶段 2 的验收结论；prompt 消融、独立留出集、最小配对反事实、人工盲评与跨模型复测仍未完成。

## 4. 当前文件职责

| 文件 | 职责 |
|---|---|
| `state.py` | 事件、完整感知、唯一人格状态和决策 trace 合同；状态/感知序列化 |

| `evaluation.py` | bootstrap 合同检查；报告会明确把阶段 2 gate 标为未通过 |
| `configs/personality_core.json` | 版本 `2026.08.22-v4` 的实验配置 |

## 5. 仍然存在、但没有伪装成“已完成”的边界

1. v0 感知仍是高精度优先的小词法规则；只处理了少量明确攻击目标和有限否定，不理解完整语义、复杂引用、反讽和指代。这也是阶段 2 需要留出集的原因，不能靠每次失败就无限补词表来宣称架构正确。
2. `working_self_refs / empathy_intensity / attention_hint` 目前是 trace 与调试输出，尚未作为独立生产决策变量消费；它们不计作已验收功能。
3. 桌面和 QQ 按项目既定部署使用不同物理库，因此二者**不共享同一瞬时 VA/CAPS**。但 QQ 的不同用户仍落在同一个 QQ 人格库：该库中的 VA 与全局 CAPS 共享，只有 `u_expect_user_kind` 按 `relationship_ref` 分开；这不是“全人格按 QQ 用户隔离”。
4. 现有 48 个样例没有独立标注来源，也不是 held-out；`stage_gate.passed` 固定为 false，直到缺失评测真实完成。
5. v0 旧数据库的历史修订没有冻结感知/配置，迁移后可以继续写新记录，但旧段无法做强审计；需要保留旧状态或另做一次明确的基线迁移，不能伪造可回放性。
6. SQLite 不能靠 `CREATE TABLE IF NOT EXISTS` 给旧表补外键；新库有事件→修订→trace 外键，旧库则由 replay 显式检查孤儿 revision / trace 并报告不一致，不伪装成已迁移出外键。
