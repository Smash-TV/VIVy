> 日期：2026.8.21

> 依据：`7_理论变量归并表.md`、`8_存档问题.md`、`9_人格理论架构.md`，并交叉检查现有工程、`5_工程落地方案.md`、`6_世界模型.md` 与 `参数校准指南.md`

## 0. 如果只看五分钟，就看这一节

人格内核 v0 不该先选“大模型、概率图、Kalman、LoRA 或向量人格”中的某一种。当前真正缺的是一条能重放、能审计、能证明没有越权写状态的最小闭环。

推荐主线只有一条：

```text
InteractionEvent + 元数据（发生了什么）
  → 廉价路由判断
  → 按需检索少量记忆或知识引用
  → PerceptState（观察 / 推断 / 不确定性，世界模型只读）
  → personality_core.reduce(...)（纯函数，唯一人格决策入口）
  → 更新 Russell 效价—唤醒与 CAPS 当轮激活
  → 在既有行动意图和四种调节策略中评分、门控
  → DecisionTrace（为什么这么选）
  → 人设提示词 + 动态约束交给 LLM 生成具体表达
  → 离散情绪标签、动作和 TTS 参数只从结果派生
  → 记录结果；离线产生 ChangeProposal，审核后才改慢变量
```

v0 的六个决定：

1. **只保留一个 `PersonalityState`。** 用户关系差异放在 CAPS 记录的 `subject_ref` 等作用域字段里；当轮工作状态是派生帧，不另建第二套人格状态。
2. **人格运算必须是确定性的纯 reducer。** LLM 可以解析语义、生成语言，但不能直接写人格、权重、依恋、自我表征或价值。
3. **`if–then signature` 是待测的情境—行为剖面，不是一堆手写规则。** v0 用少量边界规则、连续激活和可解释评分。
4. **快变量和慢变量分开。** 效价—唤醒先按真实时间向基线恢复，再受本轮事件的有界目标融合影响；依恋、自我表征、EAS、价值与连接权重在 v0 只读。
5. **事件记忆拥有证据，知识图谱拥有整理后的知识。** 不把每轮聊天复制进知识图谱，也不再造第三套原始记忆。
6. **先做行为契约和回放测试，再接真实聊天。** 没有测试集时，更复杂的学习算法只会把猜测包装得更复杂。

暂时不做：完整事件溯源架构、RDF/PROV-O 全套、动态贝叶斯网、Kalman、变化点自动改人格、神经状态模型、LoRA、persona vector、agent 自主改写 persona。这些都有适用场景，但都不是当前第一步。

## 1. 本轮调研先固定了哪些边界

以下内容来自 7/8/9，工程实现不得改写它们：

- CAPS 是主要运行框架，但学术理论没有提供唯一的软件字段、公式或学习率。
- Russell 效价—唤醒是唯一可写的连续情绪内核；离散情绪词只是按需解释或输出映射。
- EAS、依恋焦虑/回避、`self_representations`、CAPS 五类单元都按现有定义保留，不新增平行理论变量。
- 依恋四类型按需派生，不持久化；照料系统属于触发式 Skill / 插件。
- 调节 v0 只有重评、情境修改、注意转移、暂停/设立边界四种。
- Kelly 只在世界模型感知阶段按需解释，不进入 `PersonalityState`，也不建立建构图。
- OCEAN 等外部评估只能输出报告，绝不能反向驱动状态、提示词、行为或长期学习。
- AI 年龄只由知识图谱中的 `born_at` 计算。
- 只有一种 `self_representations` 记录，同时承载当前自我图式与可能自我；不能再建平行的 working model 或第二套自我系统。

本报告解决的是“这些边界如何变成一条可运行、可验证的工程链”，不是继续补理论。

## 2. 现有工程真正需要补的接口

结合当前代码，第一版不是推倒重来，而是给既有聊天链增加一个共同的、很薄的人格决策段。

### 2.1 当前已有的东西

- 桌面端和 QQ 端已经各自拥有聊天循环与记忆写入路径。
- `modules/persona.py` 与 `skills/gwen-persona/SKILL.md` 已经承担静态角色基线。
- `modules/emotion.py` 已经把回复解析为 CosyVoice 所需的离散情绪标签。
- 主动聊天模块已经负责“什么时候主动说”，不需要第二套日程 planner。
- 知识图谱目前以 Markdown 页面为源，SQLite 是可重建的索引；它适合实体、概念、来源与综合页，不适合直接充当逐条互动证据账本。

### 2.2 当前缺口

- 桌面记忆只有自增整数、角色、内容、时间；QQ 记忆多了会话作用域，但两边没有共同的稳定事件 ID、来源、结果、版本和证据引用格式。
- 当前离散情绪是在生成回复以后取得的；它可以控制 TTS，却不能反向更新效价—唤醒。否则会让模型用自己刚生成的标签证明自己的内部状态。
- 桌面与 QQ 可能同时写同一个全局人格状态，必须处理丢失更新和 SQLite 连接并发。
- 当前 KG 索引会重建，数据库行号不稳定，所以不能把索引行号当长期证据 URI。

因此只需要增加四个逻辑对象，而不是增加一串 Manager：

- `InteractionEvent`：可引用的输入、结果或外部事实；
- `PerceptState`：世界模型对这一事件的结构化观察、推断与不确定性；
- `PersonalityState`：沿用 9 的唯一人格状态；
- `DecisionTrace`：本轮前后状态、候选分数、门控和版本信息。

离线学习阶段以后再增加 `ChangeProposal`，它不是第二套状态，只是一次待审核变更。

下表先给选择结论，后续章节解释做法。

|---|---|---|---|

## 4. 运行主线的具体做法

### 4.1 先把当前事件变成 `PerceptState`

建议把感知做成一个 `perceive()`，内部按成本逐步路由，不再拆 Manager：

1. **代码可确定的事实直接写入 `items[]`，并标记 `kind: observed`。** 时间、渠道、用户 ID、是否主动聊天、是否包含图片、工具是否成功等不应交给 LLM 猜。
2. **先用事件和元数据做廉价路由。** 若出现指代、省略、关系线索或世界观实体，先检索少量记忆/KG，再形成最终 `PerceptState`；否则不检索。
3. **明确词法或协议事件用小规则。** 例如显式取消、工具报错、用户直接说“不要继续”。规则只识别事实或边界，不做人格价值判断。
4. **语音和图像通过模态 adapter 进入同一个 `items[]`。** ASR/视觉模型得到的语义一律标记为 `inferred`，并保留原音频、图像或转写引用。
5. **只有语义含糊且确实会改变决策时，才让 LLM 输出受限 schema。** 输出字段必须来自 6/9 已认可的情境特征；允许 `unknown` 和拒答，不允许临时发明新人格轴。

结构化输出可以参考 [JSON Schema](https://json-schema.org/specification)；Ollama 也支持在 `format` 中传 JSON schema，并建议用低温度降低随机性。但低温度不构成确定性保证，结构化输出也只保证形状、不保证解释正确，仍需字段校验、枚举限制和回放评测。[Ollama Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs) DeepSeek、百炼与 Ollama 的具体能力差异见 `10A_工程调研补充.md`。

最低要求：

```json
{
  "items": [
    {
      "kind": "observed|inferred",
      "content": "...",
      "source_ref": "urn:uuid:...",
      "confidence": 0.0,
      "construct_ref": null
    }
  ],
  "continuity": "...",
  "uncertainty": [],
  "parser_version": "..."
}
```

这里的“不确定性”不能直接等同于 LLM 自报的 `0.83`。应在带人工标签的留出集上测每个字段的可靠性；未校准前，低把握字段只允许“少更新或不更新”。深度模型置信度常常失准，温度缩放等方法只能在验证集上校准输出，并不能证明语义真实。[Guo 等，2017](https://proceedings.mlr.press/v70/guo17a.html)

核心回放读取已经保存并验证的 `PerceptState`，不能再次调用 LLM。确定性承诺只覆盖 `state_before + PerceptState + elapsed_time + config_version → 核心转移与候选分数`；原始文本到感知的准确率、校准和措辞鲁棒性单独评测。

积累了稳定的人工纠错标签以后，专用 Encoder 才与规则、小 LLM 在同一留出集比较；没有数据时不预建分类器。Kelly 建构只从版本化静态配置按 `scope` 匹配，不在线学习，纠错进入感知评测集。

感知必须发生在本轮人格决策之前。如果把解析放在生成回复以后，它只能供下一轮或离线审计使用，不能声称影响了当前回复。

### 4.2 效价—唤醒：先用连续时间的确定性基线回归

Russell 的环形模型给出了二维表示，但没有规定软件中的更新公式。[Russell，1980](https://doi.org/10.1037/h0077714) 后续情绪动力学研究常用连续时间的 Ornstein–Uhlenbeck 类模型表示基线回归，也强调不规则时间间隔和外部刺激的重要性。[DynAffect](https://pmc.ncbi.nlm.nih.gov/articles/PMC6433426/)、[二维 VA 的 OU 状态空间模型](https://pmc.ncbi.nlm.nih.gov/articles/PMC10051943/)、[刺激驱动的有界情绪动力学](https://pmc.ncbi.nlm.nih.gov/articles/PMC9537408/)

v0 不需要随机过程，只取其中最容易解释的确定性部分：

```text
decay = exp(-ln(2) * elapsed_seconds / half_life)
signed_sensitivity = positive_sensitivity if event_drive >= 0 else negative_sensitivity
signal = tanh(affect_intensity * signed_sensitivity * event_drive)
recovered = baseline + decay * (previous - baseline)
if signal >= 0:
    target = baseline + signal * (upper_bound - baseline)
else:
    target = baseline + (-signal) * (lower_bound - baseline)
fusion = min(clip(event_fusion_max, 0, 1), abs(signal))
next = clip(recovered + fusion * (target - recovered), lower_bound, upper_bound)
```

效价和唤醒分别计算，可有不同半衰期。`elapsed_seconds` 是 reducer 的显式输入；`event_drive` 来自已经校验的 `PerceptState`；没有新证据时只向基线恢复。`event_fusion_max` 限制单轮最多靠近目标多少，`tanh` 限制信号幅度；它们防止相同线索因调用频率反复累加到边界，但不阻止一次清晰的正负事件改变当轮情绪。

为避免参数重复，建议先固定职责：

- `affect_intensity`：本轮事件进入有界信号前的总体幅度；
- 正向/负向敏感度：只调制相应符号的效价输入；
- `expressivity`：只影响外显语言、动作与 TTS 幅度，不反写内部 VA；
- EAS `emotionality`：如果现有定义需要，只调制负性刺激下的唤醒或恢复；
- EAS `activity`：只调制行动能量、主动性或候选行动强度，不强行并入情绪公式；
- EAS `sociability`：调制社交行动候选，不等同于依恋安全感。

以上是工程职责划分，不是心理学宣称。若某一项删掉后测试表现完全不变，就应删掉重复参数。

不应使用“24 小时无人纠正就重置慢变量”之类规则。时间流逝只足以让快情绪恢复，不能构成长期人格证据。

### 4.3 CAPS：用情境特征、激活和意图评分，不做规则森林

CAPS 原论文描述的是认知—情感单元、可访问性和相对稳定的激活关系网络，并没有给出唯一的字段、权重或学习算法。[Mischel 与 Shoda，1995](https://doi.org/10.1037/0033-295X.102.2.246)

原始 `if A → X；if B → Y` 研究测量的是同一人在心理情境变化时形成的稳定行为剖面。稳定的是条件模式，不是对每种措辞硬编码一条规则。[Shoda、Mischel 与 Wright，1994](https://pubmed.ncbi.nlm.nih.gov/7965613/)、[Mischel、Shoda 与 Mendoza-Denton，2002](https://doi.org/10.1111/1467-8721.00166)

第一版可把语义记录仍放在 9 已定义的五类 CAPS 单元内，只给本轮相关记录附加可回放的激活值。无需给五类单元各建一个 Manager。

最小转移式可以先没有循环权重：

```text
recovered = baseline + decay(elapsed) * (previous_activation - baseline)
next_activation = clip(recovered + input_weight * situation_features, -1, 1)
```

行动意图和四种调节策略统一评分：

```text
score(candidate) = bias
                 + state_weight * active_caps_units
                 + situation_weight * situation_features
```

v0 的 baseline、decay、`input_weight/state_weight/situation_weight` 和候选连接全部属于版本化工程配置；激活是当轮或短期运行量。它们不得未经 7/9 审核就扩成新的持久人格字段。

然后按以下顺序选择：

1. 硬门控排除不允许的候选，例如安全、用户明确边界、工具不可用；
2. CAPS 对剩余候选做价值性评分；
3. 生产模式选最高分并记录所有候选分数；
4. LLM 只把已选意图实现成自然语言、动作和表情。

CAPS 确实有循环激活网络的计算演示，但论文中的随机权重和 `0.98` 保留率只是概念模拟，不能当澄音参数。[Shoda、LeeTiernan 与 Mischel，2002](https://doi.org/10.1207/S15327957PSPR0604_06) 因此只有当无循环的基线在受控测试中确实无法表现跨单元影响时，才增加少量稀疏连接 `W`，并逐条说明其含义。

动态贝叶斯网、HMM、Kalman 或神经状态模型都可以表达更复杂的隐状态，但当前没有足够序列标签来辨识参数。[Murphy 的 DBN 论文](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2002/8174.html) 在可解释基线的留出集结果明显不足以前，不应引入。

### 4.4 `if_then_signatures` 应如何初始化和验证

不要先写“被拒绝就怎样、被夸奖就怎样”的庞大规则库。先建立一组 bootstrap 情境—行为契约：

- 只从既有世界模型字段中选 6 个最重要的情境特征；
- 每个特征做高/低两个反事实条件；
- 每个条件至少写 4 个表面措辞不同、心理意义相同的变体；
- 得到 24 组单特征反事实对、共 48 个最小情境；
- 间隔运行两次，记录结构化行动意图和策略，而不是逐字比较回复。

【2026.8.22 工程审计补充】六个是用于 bootstrap 情境—行为剖面的主要连续输入，不限制世界模型增加高精度的**瞬时事件分类**。v3 额外使用 `assistant_directed_attack / user_boundary / surprise_cue` 区分对象与事件类型；它们不是人格特质，也不能为了凑到“9 个特征”另立评测轴。现有 48 个文件没有共享的最小 pair 设计，只能叫手写合同组；在重新制作真正的 pair_id 和最小差异刺激前，不得声称已得到 24 组反事实对。

这 48 个情境只是启动夹具，不是研究证明的充足样本。经典 CAPS 研究用跨时间的个体内情境—行为剖面相关检验稳定性；后续 HRWP 方法还用个体内部回归斜率操作化 `if–then`，并强调每个条件需要多个刺激，避免把单条文案的偶然性质当人格。[HRWP 方法](https://pmc.ncbi.nlm.nih.gov/articles/PMC3925438/)

因此 `if_then_signatures` 更适合保存：

- 条件特征或受控情境集引用；
- 预期的行动倾向方向，而不是固定台词；
- 支持与反驳证据引用；
- 最近一次验证结果和配置修订；
- 统计剖面或斜率（数据足够以后）。

### 4.5 调节和 planner 的职责

世界模型只报告情境与不确定性。是否重评、修改情境、转移注意、暂停/设立边界，是 CAPS 基于价值、预期、目标和能力做的决定。

planner v0 只是一个路由门：

| 条件 | 动作 |
|---|---|
| 时间、渠道、发送者等明确元数据 | 直接进入 `observed` |
| 语义含糊且会影响人格决策 | 调用小型结构化感知 |
| 出现前文指代、关系线索或历史承诺 | 检索记忆 |
| 涉及世界观实体或 `born_at` 等事实 | 查询 KG |
| 既有建构解释与当前决策都相关 | 按需运行 Kelly 感知解释 |
| 出现脆弱、求助或安全线索 | 建议触发照料 Skill，由现有边界决定是否执行 |
| 无命中 | 明确记录 skip 原因 |

这可以是一个纯函数和配置表。只有以后出现复杂分支、暂停恢复、人工审批等真实需求，才评估状态图框架。[LangGraph 的 reducer/state 文档](https://docs.langchain.com/oss/python/langgraph/graph-api) 可以借鉴“显式状态 + reducer”的思想，但当前无需引入依赖。

现有主动聊天继续决定“什么时候说”；人格内核只决定“当前倾向做什么”；人设与 LLM 决定“具体怎么说”。

### 4.6 静态人设、LoRA 与 persona vector

当前最稳妥的组合是：

```text
gwen-persona/SKILL.md 的静态角色基线
+ 本轮检索到的必要事实
+ personality_core 给出的短小行动/表达约束
→ LLM 生成
```

不要把整个 `PersonalityState`、审计日志或大量量表分数塞进 prompt。模型只需看到本轮允许知道、且会影响表达的派生约束。

LoRA 适合在有固定目标语料时学习相对静态的风格或说话方式，并不适合保存每轮变化的情绪和关系状态。[LoRA 原论文](https://arxiv.org/abs/2106.09685) 启用门槛应是：已有稳定 prompt 基线、角色语料有明确许可、训练/留出集分离，并且 LoRA 在盲评中显著优于 prompt，同时不破坏工具调用与安全能力。

Persona vectors 可以用于白盒模型内部的特质监测或激活 steering，但当前论文主要在 Qwen2.5-7B-Instruct 与 Llama-3.1-8B-Instruct 等少量模型、有限特质和多为单轮问题上验证，也承认单轮设置的局限。[Persona Vectors](https://arxiv.org/abs/2507.21509) 它可作为后期 A/B 实验，不能作为跨 DeepSeek、百炼和 Ollama 后端的统一人格状态。

## 5. 证据链、知识图谱与 8 中 O 问题的推荐答案

### 5.1 总原则

```text
聊天/工具/外部结果的原始事实 → InteractionEvent 所有
整理后的实体与相对稳定知识 → KG 页面所有
人格为何改变 → ChangeProposal + StateRevision 所有
摘要、embedding、外部评估 → 都只是可重建派生物
```

这不是把整个应用改成 event sourcing。完整事件溯源会带来版本迁移、物化视图、事件演化和查询复杂度；它只在审计与重放收益足够高的部分值得使用。[Microsoft Event Sourcing Pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing) 当前只需要保留人格决策所引用的事件、状态修订和快照。

W3C PROV-O 可提供少量可靠语义：Entity、Activity、Agent，以及 used、wasGeneratedBy、wasDerivedFrom、wasRevisionOf、wasInvalidatedBy。规范明确允许只使用所需子集。[W3C PROV-O](https://www.w3.org/TR/prov-o/) 不需要把项目改造成 RDF，也不需要 v0 引入 RDF-star。

### 5.2 对 O-1～O-7 的逐项建议

#### O-1：知识图谱对象粒度

v0 保持当前页级对象：实体、概念、来源、查询、比较、综合。互动事实不转成 KG 页面。若以后确实需要一句话级别的可争议事实，再增加最小 `Claim` 记录，而不是先拆整个 wiki。

#### O-2：事实的来源、时间、置信和支持/反驳怎么记

只有确有声明级查询需求时，增加：

```text
claim_id
subject_ref / predicate / object
source_refs[]
supports[] / refutes[]
valid_from / valid_to
recorded_at
generated_by
revision_of / invalidated_at
```

“自我表征的 confidence”表示主体对该自我看法的确信程度；“证据强度”属于证据链。两者绝不能共用一个字段。

#### O-3：事件记忆与 KG 是否重复保存

不重复。事件库保存发生过什么，KG 或 Claim 只保存整理后的结果并用 `source_refs` 指向事件。摘要也只保存 `derived_from` 引用。

#### O-4：稳定 URI、删除、合并与迁移

v0 使用标准 UUID URN：`urn:uuid:<uuid4>`。[RFC 9562](https://www.rfc-editor.org/rfc/rfc9562.html) 当前项目支持的 Python 版本可以直接用标准库 `uuid4`；不要为了时间有序 ID 先加 UUIDv7 依赖。

- 数据库自增 ID 只作本地索引，不作证据 ID；
- 删除时让解析器返回 `deleted/invalidated`，不让旧引用悄悄指向别的内容；
- 在隐私策略允许时保留只含 ID 与失效信息的 tombstone，原内容必须删除；
- 合并用 `superseded_by` 或 `wasRevisionOf`，不复用旧 ID；
- 迁移时保持 UUID，不把路径、表名或行号编码进 URI。
- 来源删除或失效后，未决 proposal 和依赖它的已批准 revision 都标记为“证据失效、待重评”；通过回放生成新 revision，绝不静默改写历史。

#### O-5：人格学习读什么，谁有写权限

学习器读取规范化事件、可验证结果和明确来源的 Claim；可以查看摘要以召回候选，但最终每个变更都必须追溯到原始引用。感知或证据抽取结果须连同输入引用、provider/model、prompt、schema 与规则版本固定保存，回放读取旧标注而不重新调用 LLM。只有人格状态更新器能提交新 revision；LLM、世界模型、记忆摘要器、KG 和外部评估都没有直接写权限。

不能把模型自己的回复当成“澄音本来就是这样”的学习证据，也不能把普通的用户继续聊天或赞同当通用奖励信号，否则会形成自证循环和迎合偏差。

#### O-6：摘要保存什么

摘要是可重建缓存，至少保存 `summary_id`、`derived_from[]`、生成器/提示词版本、创建时间和失效状态。源事件删除、合并或判错时，摘要应失效或重算；摘要本身不是人格变化的最终证据。

#### O-7：慢变量使用什么更新器

不建立一个对所有字段通用的 `SlowVariableManager`。按可观测性分开：

| 字段 | v0 | 有足够数据以后 |
|---|---|---|
| 效价—唤醒 | 在线确定性 reducer | 只有出现有标签的观测噪声时，才比较 Kalman/连续时间状态空间 |
| 关系性预期/信念 | 先只记录支持与反驳事件 | 对明确定义的二元结果可用 Beta-Binomial；连续结果可比较保守 EMA |
| `if–then_signatures` | 受控情境契约与重复测量 | 数据足够后估个体内剖面/斜率；真实日志仅作辅助 |
| 依恋焦虑/回避 | 只读 | 多次、跨时间、跨情境证据形成提案，人工批准 |
| 自我表征 | 只读；用户明确表达也先形成候选 | 证据引用、矛盾检查、人工批准后修订 |
| EAS、价值、目标、连接权重 | 只读 | 只有专门验证设计和版本评审后才可能改变 |
| 变化点 | 不启用 | 以后只触发“需要审查”警报，不直接改人格 |

### 5.3 离线慢学习的最小流水线

```text
1. 从 watermark 以后选择合格事件
2. 按目标字段与关系作用域分组
3. LLM 只抽取结构化 evidence candidate
4. 确定性校验：引用存在、结果可观察、重复、跨情境、矛盾、隐私
5. 字段专属估计器生成有界 delta
6. 在历史情境上回放，并运行不变量与人格漂移检查
7. 生成 ChangeProposal，展示 old/new、证据、反证和影响
8. 需要批准的字段由人确认
9. 提交新的 StateRevision；保留一键回滚到上一 revision
```

回滚不是删除历史，而是创建一个指向旧快照的新 revision。这样仍能解释“何时、为什么撤销”。

## 6. 最小数据契约

以下只展示工程元数据，不改写 9 中已经定义的理论字段。

### 6.1 `InteractionEvent`

```json
{
  "event_id": "urn:uuid:...",
  "source_id": "installation-or-channel-id",
  "stream_id": "relationship-or-global-stream",
  "stream_seq": 42,
  "schema_version": 1,
  "occurred_at": "2026-08-21T10:00:00+08:00",
  "recorded_at": "2026-08-21T10:00:00+08:00",
  "channel": "desktop|qq|tool|system",
  "actor_ref": "...",
  "relationship_ref": "...",
  "session_ref": "...",
  "kind": "message|tool_result|feedback|system_event",
  "payload": {},
  "source_refs": [],
  "causation_ref": null,

```

UUID 负责全局引用，`stream_seq` 负责严格重放顺序；即便以后使用 UUIDv7，也不能省掉流内序号。桌面和 QQ 可以继续物理分库，但要通过适配器输出同一逻辑契约。桌面端还需先确定稳定的 `actor_ref/relationship_ref`；在身份不明确时不得把关系证据混进全局人格。


`decision` 是非持久化派生输出，放进 trace 只是为了审计，不是第二套人格状态。生产日志可以对敏感正文做脱敏或引用，不必在 trace 里复制聊天内容。

## 7. SQLite 与并发：当前有一个必须先处理的现实风险

人格状态写入需要：

- 唯一约束 `UNIQUE(event_id)` 只能防重复写，不能单独证明幂等；同一 `event_id` 的重试必须具有相同不可变语义；
- 最终状态提交事务必须确认原始事件已入账，以账本还原的权威事件运行 reducer；尚无 revision 的首次投影还要核对 v0 确定性感知没有与事件错配，已有 revision 的合法重试则读取冻结结果，不用当前配置重判历史；新库同时用事件 / revision 外键兜底；
- `outcome` 按 JSON 可还原值比较，第一个非 NULL 结果生效，重试不得覆盖已有结果；空字典也是有效结果；
- 旧表无法由 `CREATE TABLE IF NOT EXISTS` 自动补外键，冻结回放必须显式报告孤儿 revision / trace；
- 短事务与 `busy_timeout`；
- 乐观版本检查，例如 `UPDATE ... WHERE revision = :old_revision`；
- 为状态提交分配单调 `applied_sequence` 与 `applied_at`；冲突时按流内顺序读取最新状态并重放，不能后写覆盖先写；
- 状态快照、revision 和 trace 在同一事务提交；
- 数据库仅放本机磁盘，不放网络文件系统。

迟到事件保留原 `occurred_at`，但 v0 按实际提交顺序生成新的当前 revision，不倒改已经发生的历史回复；若它修正或否定旧证据，则由离线回放生成新的 revision，并保留旧 trace。若原始事件和人格投影位于不同 SQLite 文件，事件是权威、状态是幂等投影，部分失败按 `event_id` 重试。

v0 建议先使用 SQLite 默认 rollback journal 和短 `BEGIN IMMEDIATE` 写事务，不要不加检查地开启 WAL。

原因不仅是“一次只有一个 writer”。SQLite 官方在 2026 年披露 WAL-reset bug：3.7.0 到 3.51.2 在两个以上连接同时写入/检查点的极小概率竞态下可能损坏数据库；修复版本是 3.51.3，部分旧分支回补为 3.50.7、3.44.6。[SQLite WAL 官方说明](https://sqlite.org/wal.html#the_wal_reset_bug)

本次本机检查到的两个 Python SQLite 版本分别为 3.50.4 和 3.45.3，均不在已修复版本内。虽然官方判断概率很低，当前也没有理由为 v0 冒这个风险。升级并验证修复版本、完成双进程压力测试以后，如读写延迟确实需要，再启用 WAL。WAL 仍然只有一个 writer，并且需要正确处理 checkpoint。[SQLite WAL 并发](https://sqlite.org/wal.html#concurrency)

## 8. 校准与评测：怎样知道实现真的有用

### 8.1 先修正几种不可靠的校准思路

- 人类量表百分位不能直接线性映射成 AI 内核参数；最多作为外部描述或初始讨论材料。
- `0.1`、`0.2`、`0.3`、24 小时、50% 等若没有项目数据，只能标成实验初值，不能写成心理学阈值。
- `self_representations.confidence` 是主观确信，不是事实准确率，也不是证据权重。
- 无人纠正不是正证据；用户继续对话也不是所有人格目标的奖励。
- 离散情绪标签、OCEAN 结果、LLM judge 分数都不能反向写 VA 或慢变量。

EAS、依恋、自我表征等 v0 只读项的第一组值来自版本化角色设定：沿用 7/9 的数值范围，先给实验初值，在受控情境上人工校准并锁定 config revision。它们不能由人类量表百分位自动映射，也不能在缺少证据时由 LLM 补齐。

### 8.2 四层评测

#### A. 不变量与权限测试

- 同一 `state_before`、已验证 `PerceptState`、`elapsed_time` 和 `config_version` 得到同一核心转移与候选分数；
- VA、激活、依恋轴等不越界；
- 无刺激时只按真实时间向基线恢复；
- 改变定时器调用频率不改变同一总时长的恢复结果；
- 世界模型、KG、外部评估、TTS 标签没有人格写接口；
- 依恋四类型不持久化；
- 运行 OCEAN 前后 state/config hash 不变；
- 年龄查询只来自 `born_at`；
- 删除或失效证据后，相关 proposal 与已批准 revision 都进入待重评状态。

#### B. CAPS 情境—行为契约

使用 4.4 的 24 组反事实对、48 个 bootstrap 情境，测：

- `profile_stability`：两次运行的连续候选分数或预定义行为维度剖面的 Spearman/Pearson 相关，不能直接对类别型 `selected_intent` 求相关；
- `counterfactual_accuracy`：只改变一个目标特征，结构化决策是否按预期方向改变；
- `paraphrase_invariance`：心理意义相同、措辞不同，意图是否一致；
- `feature_slope`：目标特征对行为倾向的个体内斜率；
- `state_recovery_error`：刺激后的恢复曲线是否符合配置；
- `intent_text_agreement`：最终台词是否忠实实现已选意图。

通过阈值应由项目在基线实验后确定，不能冒充学界统一临界值。

#### C. 消融

至少比较：

1. 仅人设 prompt；
2. 人设 prompt + 记忆；
3. 人设 prompt + VA 状态；
4. 人设 prompt + 完整 CAPS 决策 + 记忆。

只有复杂模块在留出情境上稳定优于简单基线，才保留它。Stanford Generative Agents 也比较了 observation、planning、reflection 的消融；其 `perceive → retrieve → plan → reflect → execute` 边界值得参考，但完整日程模拟和高频 LLM 调用不适合直接照搬。[论文](https://arxiv.org/abs/2304.03442)、[代码](https://github.com/joonspk-research/generative_agents)

#### D. 外部角色评测，只读

- [CharacterEval](https://aclanthology.org/2024.acl-long.638/)：更贴近中文角色对话，可借其角色一致性和对话场景设计；
- [PersonaGym](https://aclanthology.org/2025.findings-emnlp.368/)：覆盖预期行动、理由、语言习惯、角色一致性与有害行为控制，可借其自由文本 persona 评测框架；
- [InCharacter](https://aclanthology.org/2024.acl-long.102/)：用心理量表访谈角色，可生成外部报告，但必须遵守本项目“评估不得反向驱动”的边界。

自动 LLM judge 只适合回归报警；少量关键情境仍应做人类盲评和两两比较。对结构化感知字段，应同时报告校准误差、选择性准确率与 coverage；模型允许 abstain 时，不能只报告“回答过的问题有多准”。[选择性预测的重复采样方法](https://aclanthology.org/2023.emnlp-main.35/)、[LLM abstention 评测](https://aclanthology.org/2025.coling-main.627/)

## 9. 一根可执行的分阶段主线

每一阶段只有一个目标；前一阶段没有验收，不进入下一阶段。

### 阶段 0：先做契约与回放台架

产物：

- `InteractionEvent`、`PerceptState`、`DecisionTrace` 和 state revision schema；
- 48 个受控情境 JSON 与少量人工确认的预期方向；
- 纯 reducer 的接口和不变量测试；
- 稳定 UUID 引用、幂等与并发提交测试。

通过条件：同一已验证 `PerceptState`、旧状态、时间差和配置版本可重复得到相同核心转移与候选分数，所有禁止写路径都有自动测试；原文到感知的稳定性另行报告。

### 阶段 1：只跑通 VA 垂直切片

```text
固定情境 JSON → PerceptState → VA 基线恢复/有界目标融合 → 表达约束 → DecisionTrace
```

EAS、依恋、自我表征、CAPS 慢内容全部只读。先离线跑曲线，再接桌面端一个入口。离散情绪仍只用于输出。

通过条件：边界、时间恢复、不同调用频率等价、重放一致性全部通过。

### 阶段 2：加入 CAPS 意图、签名与四种调节

先使用无循环权重的可解释评分。planner 只有出现真实的生产路由消费者时才建立；2026.8.22 审计已删除只在调试页回显、生产链不消费的占位实现。48 个 bootstrap 样例先检查显式合同；稳定性、反事实敏感性和措辞泛化必须另用留出集与真正配对设计验证。

通过条件：完整方案在留出情境上优于“仅 prompt / prompt + 记忆”基线，且每次选择都能从 trace 解释。

### 阶段 3：接入桌面与 QQ 两条真实链

两边通过同一 adapter 调用人格内核；主动聊天只管触发时机；TTS 标签在决策以后派生。加入 SQLite revision CAS、幂等和双进程压力测试。

通过条件：重复事件不重复改变状态，并发无丢失更新，任一渠道都不能绕过唯一 reducer。

### 阶段 4：只上线“提案式”慢学习

先只选择一个可清晰观察结果的关系性预期做试点。LLM 抽证据，确定性程序校验和估计，人审核后提交 revision。依恋、自我表征、EAS 和价值仍不自动更新。

通过条件：任一变更都能列出支持/反驳证据、通过回放、可回滚；删除证据会使提案失效。

### 阶段 5：有真实需求才补 Claim 级 KG

只有出现跨页面事实冲突、声明级溯源或 llm-wiki 查询需求时，才实现 5.2 的最小 Claim。否则继续使用“KG 页 + 事件引用”。

### 阶段 6：最后才做模型层人格实验

以稳定 prompt 基线为对照，分别 A/B LoRA 或 persona vector；单独测角色一致性、工具调用、安全与后端可移植性。动态状态仍由内核拥有，模型层不得成为真值源。

## 10. 建议的最小文件落点

真正编码时保持一层，不预建空框架：

```text
src/gwen_agent/modules/personality_core/
  state.py        # 现有理论字段的数据契约与校验
  perception.py   # event → PerceptState 的薄适配
  runtime.py      # 纯 reducer、候选评分、门控、trace
  store.py        # SQLite snapshot/revision/trace，幂等与 CAS

configs/personality_core.json
data/personality_core.db
tests/unit/test_personality_core_runtime.py
tests/unit/test_personality_core_contracts.py
tests/integration/test_personality_core_chat_flow.py
tests/fixtures/personality_core_scenarios/
```

阶段 4 到来前不要创建 `learning.py`。若 `state.py` 与 `runtime.py` 仍很短，也可以先合成一个模块；删除一层后仍清晰就不加层。

需要改造的既有入口：

- 桌面 `ChatBackend` 与 QQ `GwenAgent`：在最终生成之前调用同一个 runtime；
- `memory.py` / `qq_memory.py`：通过 adapter 输出统一事件契约，不必马上物理合库；
- `emotion.py`：保留输出标签映射，明确禁止反写 VA；
- `persona.py`：保留静态基线，只注入本轮派生约束；
- `utils.py`：增加配置和数据路径常量，避免硬编码绝对路径。

## 11. 可以借鉴但不应直接照搬的项目

- [Generative Agents](https://github.com/joonspk-research/generative_agents)：借阶段边界、记忆/短期状态分离和消融；不搬完整日程模拟。
- [Concordia](https://github.com/google-deepmind/concordia)：借 agent state、memory、reasoning 与外部 world state 的边界；不搬 Game Master 社会模拟。
- [Letta](https://github.com/letta-ai/letta)：借 persona/human/检索记忆的分区思想；不允许 agent 自主编辑 persona block。
- [LangGraph](https://github.com/langchain-ai/langgraph)：借 reducer、checkpoint、replay 思想；真实出现复杂分支前不加依赖。
- [JsonLogic](https://jsonlogic.com/)：规则真正多到需要配置化时再评估；当前几条门控直接写纯函数更简单。

## 12. 结论

人格内核第一版的价值不在于“像人脑一样复杂”，而在于这四件事同时成立：

1. 同一个心理情境能稳定地产生澄音特有的条件行为模式；
2. 情境变化时，行为能按可解释的方向变化；
3. 任一状态变化都有事件引用、版本和回放路径；
4. LLM、外部量表、摘要和 TTS 都无法绕过唯一写入口。

先完成“事件 → 感知 → 纯 reducer → CAPS/VA → 意图 → 表达 → trace”这一条垂直切片。它跑稳以后，慢学习、知识声明、LoRA 或 persona vector 才有可靠的比较基线；在此之前，它们只会扩大不确定性。
