# 世界模型 · 感知架构

> 版本：v0.4（2026-08-20）
> 状态：已确定总体定位与 Kelly 建构的运行归属，具体模型与数据结构仍待实验
> 定位：记录澄音世界模型中已经确定的设计边界；本文不替人格内核选择公式、神经网络、潜空间或混合落地方案。

---

## 1. 项目内定义

澄音的世界模型以**拟合感知**为核心：把文本、语音、图像、时间与设备环境等现实输入，整理成澄音在当前时刻所感知到的情境，再交给人格内核处理。这里的“感知”既包括可追溯的观察，也包括澄音用个人认知区分对观察作出的有限解释；两者必须明确分开。

这里的“世界模型”是项目内的特定定义，不等同于自动驾驶、机器人或强化学习研究中用于生成未来画面、模拟物理环境和规划动作的完整世界模型。澄音当前需要解决的问题是：

> 面对连续、零散且可能含糊的现实信息，澄音此刻认为发生了什么；哪些是直接证据，哪些只是推测；她对这个判断有多大把握。

世界模型不直接决定澄音产生什么情绪、满足什么需要、如何看待与用户的关系，也不负责生成最终回复。这些仍属于人格内核与语言模型的职责。

---

## 2. 已确定的设计结论

1. 世界模型的核心目标是感知拟合，不是视频生成或完整世界模拟。
2. 输入理解原则上可由小参数量 LLM 承担；具体模型、本地或云端部署方式尚未确定。
3. 确定性的时间、来源、设备状态等信息直接用算法读取，不经过 LLM 重复解释。
4. 世界模型只输出一份统一的感知状态，供人格内核、主动聊天和回复生成共同使用。
5. 感知结果必须区分直接观察与模型推测，并保留来源和置信度。
6. 世界模型可以读取互动记忆和知识图谱检索出的线索，但不承担长期记忆存储。
7. Kelly 个人建构的**执行位置**确定为世界模型的感知解释阶段；项目明确不采用建构图、RepGrid 或建构关联网络，它也不进入 `PersonalityState`，不由 CAPS 重复分类。
8. SEG 方案已否决，不作为感知、记忆或世界模型的候选实现，也不预留对应分支。

---

## 3. 职责边界

### 3.1 世界模型负责

- 接收当前可用的现实输入；
- 从输入中提取人物、对象、事件、时间和上下文线索；
- 过滤无关信息，判断当前值得注意的内容；可以读取上一时刻人格状态给出的 `attention_hint`，但不自行决定澄音应该回避或关注什么；
- 把连续输入与上一时刻的感知连接起来；
- 使用检索出的记忆线索辅助理解当前情境；
- 在确有解释价值时，按需用 Kelly 式双极建构对人物或事件作推测性分类；
- 区分直接证据、合理推测和未知信息；
- 输出带来源与置信度的统一感知状态。

### 3.2 世界模型不负责

- 保存互动记忆或知识图谱；
- 融合六套人格理论；
- 更新情绪、需要、依恋等人格变量；
- 决定澄音的价值判断和关系立场；
- 生成最终自然语言回复；
- 生成视频或重建完整物理环境；
- 训练 Actor、Critic、奖励函数或强化学习策略；
- 对未来世界进行长时间、多分支模拟。

### 3.3 Kelly 建构在世界模型中的边界

Kelly 的个人建构理论关心个体用什么区分方式解释和预测经验，因此它适合放在本项目的感知解释步骤。但“放进世界模型”不代表把主观解释伪装成客观事实，也不代表把整套人格计算搬进感知层。

最小处理规则如下：

1. 先保存观察，例如“用户比约定时间晚两小时回复”；
2. 只有当前事件与某个建构的适用领域匹配时，才产生解释，例如沿“重视承诺—敷衍承诺”作暂时判断；
3. 解释记录为 `inferred`，引用观察证据，并带独立置信度；
4. 没有合适建构、证据不足或存在多种合理解释时，保持未分类或列入 `uncertainty`；
5. CAPS 可以读取这一解释，但仍要结合情绪、关系历史、目标和价值决定“这对澄音意味着什么”。

工程上确定不采用 RepGrid、建构图、建构关联网络或 `permeability` 全局分数；这不是仅限第一版的临时删减。当前只保留一份可解释的双极建构列表；某个建构只有遇到真实的适用范围问题时才增加 `scope` / `range_of_convenience`。当前对象与建构的匹配由同一 `perceive()` 管线完成，不新增“建构识别器”。建构词表如何从长期经验更新尚未确定；初版可以静态配置，纠错记录先进入评测数据，不在线改写。

### 3.4 与人格调节策略的边界

世界模型的感知与 CAPS 的调节会形成闭环，但不合并成同一职责：

- 世界模型负责报告“发生了什么、证据是什么、判断有多确定”；
- CAPS 根据澄音的情绪、目标、价值和关系边界，决定是否重评、修改情境、转移注意或暂停；
- 如果 CAPS 选择注意转移，只向下一轮 `perceive()` 提供一个 `attention_hint`，由同一感知管线执行输入筛选；
- 如果 CAPS 选择情境修改或设立边界，那是对外行动；世界模型只在下一轮观察行动后的实际结果；
- 世界模型不得为了让澄音舒服而改写事实、降低证据置信度或替她作价值判断。

这样复用现有 `perceive()` 和人格运行循环，不需要建立独立“调节管理器”，也不会让感知模块同时承担价值性决策。

## 4. 与人格、记忆的关系

世界模型、人格内核和记忆系统不是三套相互替代的系统：

```text
现实输入 ───────────────┐
当前时间与环境 ─────────┤
互动记忆 / 知识图谱线索 ┤
上一时刻的感知状态 ─────┤
上一时刻的人格状态 ─────┘
             ↓
     世界模型：形成当前感知
             ↓
        PerceptState(t)
             ↓
   人格内核：解释、评价与产生倾向
             ↓
        人格状态与回应约束
             ↓
          LLM 生成表达
```

三者分别回答不同问题：

- **世界模型**：澄音现在感知到发生了什么，哪些个人建构解释暂时适用？
- **记忆系统**：哪些过去经历可以为当前感知提供线索？
- **人格内核**：这些感知与解释在她的情绪、预期、目标和价值中意味着什么，她会产生怎样的倾向？

上一时刻的人格状态可以影响本轮注意力和感知敏感度，例如澄音可能更容易注意到关系变化或威胁线索；本轮感知再进入人格内核，得到新的人格状态。使用上一时刻状态可以避免同一轮发生无限循环：

```text
PersonalityState(t-1)
          ↓
      perceive(t)
          ↓
    PerceptState(t)
          ↓
 personality_runtime(t)
          ↓
PersonalityState(t)
```

人格运行时内部采用公式、规则网络、神经网络、潜空间还是混合方案，仍是后续讨论重点，本文不作决定。

## 5. 单一感知管线

为避免把感知提前拆成多层管理器，运行时只保留一个 `perceive()` 入口。下面是同一管线内部的处理顺序，不代表需要建立对应数量的类：

```text
接收输入
  → 读取确定性元数据
  → 理解文本 / 语音 / 图像内容
  → 结合时间连续性与记忆线索
  → 按需应用 Kelly 双极建构作推测性解释
  → 标记证据、推测和未知
  → 计算置信度
  → 输出 PerceptState
```

### 5.1 输入理解

- 文本中的语义、指代、隐含事件和模糊表达，原则上由小参数量 LLM 解析；
- 时间戳、距离上次互动多久、输入来自桌面端还是 QQ 等确定性数据，直接由算法读取；
- 没有图像时不运行视觉模型，没有语音时不运行语音特征提取；
- 小模型无法可靠判断时，应保留“不确定”，而不是补全成事实。

### 5.2 时间连续性

感知不是把每轮对话当成互不相关的独立文本。世界模型至少需要知道：

- 当前时间；
- 距离上一事件经过多久；
- 当前输入是在延续旧事件，还是开始新事件；
- 某项信息是刚刚发生、正在持续，还是用户在回忆过去。

### 5.3 记忆只提供线索

互动记忆库和知识图谱仍是事实来源。世界模型只接收检索结果中的少量相关线索，并在感知结果中保留来源引用。

Embedding 若以后启用，也只帮助记忆系统找到线索，不进入世界模型充当“记忆本身”。

### 5.4 建构解释不另开管线

Kelly 建构匹配只是 `perceive()` 内的一个可跳过步骤：先从已经识别的对象、事件和领域中寻找适用建构，再把解释写回同一份 `items`。它不需要调用第二个 LLM；小参数量 LLM 已经完成语义理解时，可以同时给出候选建构与置信度，确定性的 `scope` 匹配则可由普通算法完成。

只有在以下条件同时成立时才运行：当前信息不只是事实转写、某个既有建构与事件领域匹配、该解释会影响后续预测或人格计算。纯事实查询、没有相关建构或证据过少时直接跳过。

## 6. `PerceptState` 接口草案

下面的数据只用于约束模块边界，不代表字段与载体已经最终定型：

```json
{
  "timestamp": "2026-08-19T20:30:00+08:00",
  "situation": "用户正在确认 Kelly 建构与世界模型的设计边界",
  "items": [
    {
      "content": "用户明确提出 Kelly 理论放在世界模型处理",
      "kind": "observed",
      "source_ref": "current_message",
      "confidence": 1.0
    },
    {
      "content": "这是一项已作出的架构归属决定，不是待比较候选",
      "kind": "inferred",
      "construct_ref": "decided_pending",
      "source_ref": "current_message",
      "confidence": 0.96
    }
  ],
  "continuity": "continues_previous_discussion",
  "uncertainty": []
}
```

设计约束：

- `observed` 和 `inferred` 使用同一种记录结构，只通过字段区分，不建立两套对象；
- 每项判断必须能追溯到当前输入、设备信息或某条记忆线索；
- `construct_ref` 是可选字段，只能附在推测性解释上；它引用所用双极建构，不能反向把 `inferred` 升格为事实；
- 置信度表示世界模型对感知判断的把握，不等于事实的重要程度；
- 情绪、需要、依恋、表达风格等人格状态不放入 `PerceptState`；
- 后续如果删除某个字段仍不影响边界表达，就不保留该字段。

## 7. 感知纠错与后续学习

世界模型当前只确定“需要能够被纠正”，尚未确定采用在线学习、离线训练还是规则校准。

当用户指出“你理解错了”时，系统至少应保存：

```text
当时输入
原感知结果
用户纠正内容
被纠正的判断
原置信度
所用建构（如有）
```

这些记录可以成为以后比较小参数量 LLM、Encoder、规则或学习模型的共同评测数据。是否把纠正结果写入模型权重、提示词、规则或训练集，留到人格与学习方案选型时讨论。

---

## 8. 评测标准

世界模型不以“生成内容是否精彩”为评价目标，而以感知是否可靠为核心：

| 指标 | 检查的问题 |
|---|---|
| 事实提取 | 是否正确识别人物、事件、时间和明确陈述 |
| 含糊理解 | 是否正确处理指代、省略、反话和上下文延续 |
| 时间连续性 | 是否能区分过去、现在、持续事件和新事件 |
| 证据可追溯 | 每个判断能否找到输入或记忆来源 |
| 置信度校准 | 不确定时是否承认不确定，错误时是否过度自信 |
| 建构解释有效性 | 是否只在适用领域使用相关建构，并保持观察与解释分离 |
| 人格解耦 | 是否避免提前替人格内核做情绪和价值判断 |
| 成本与延迟 | 小参数量 LLM 与其他组件是否满足在线交互要求 |

---

## 9. 尚未确定的问题

以下内容不能因为建立了本架构文档而被视为已经选型：

1. 小参数量 LLM 的具体模型、参数规模和部署位置；
2. 语音与视觉输入分别使用什么 Encoder；
3. `PerceptState` 最终字段及其是否需要向量表示；
4. 记忆检索在感知前运行一次，还是在感知中按需补充；
5. 感知置信度如何校准；
6. 是否需要训练专用感知模型；
7. 感知纠错采用在线更新还是离线学习；
8. 人格状态以何种强度反向影响下一轮注意力；
9. Kelly 建构词表的最小配置格式、`scope` 匹配方式以及长期更新证据门槛；
10. 六套人格理论如何融合、情境如何改变动态变量、长期经历如何改变慢变量；
11. 静态澄音人格最终由 Prompt、LoRA、人格向量、模型权重还是其他载体承载。

第 10、11 项属于接下来的人格工程讨论重点，不在世界模型中提前解决。
