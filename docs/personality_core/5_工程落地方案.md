# 人格内核 · 工程落地方案选型

> 版本：v1.0（2026-08-18）
> 定位：汇总"人格内核如何工程落地"的方案讨论——用户提出的三个方案 + 补充方案 + 推荐组合。本文只做**方案选型**，不包含实施计划（实施计划由用户另行思考）。

---

## 1. 约束与衡量标准

落地的三个核心约束：

- **算力成本**：训练、推理、解析的 token 与算力总开销；
- **运行速度**：每轮对话端到端延迟；
- **拟合度**：人格表现得"像不像澄音、准不准"，进一步拆成两个指标：
  - **静态人设贴合度**：语气、价值观、口头禅像不像澄音；
  - **动态状态响应度**：情绪、需要、依恋等状态变化是否准确反映。

衡量标准（在三大约束上扩展出四个指标 + 可校准性）：

| 指标 | 含义 |
|---|---|
| 算力成本 | 在线推理 + 训练 + 解析的总成本 |
| 运行速度 | 每轮对话端到端延迟 |
| 静态贴合 | 语气/价值观/口头禅像不像澄音 |
| 动态响应 | 情绪/需要/依恋状态变化是否准确 |
| 可校准/防漂移 | 参数能否校准、能否防止人格漂移 |

## 2. 用户提出的三个方案

### 方案一：神经网络（人格入黑盒）

**描述**：训练出一个大模型 / checkpoint / DB，训练可在云端进行以承担训练成本。把"人格"放进大模型这个黑盒中运行，更接近人类的实际情况；大模型可以承载人格变量中的许多参数。

**优点**：
- 静态贴合度最高——人格内化在权重里，最"像人"；
- 推理时无额外状态管理，链路简单。

**缺点 / 坑**：
- 人格变量中大部分是**运行时动态状态**（效价—唤醒情绪坐标、依恋维度等会随交互变化），塞进权重等于"状态一变就要改权重"，不现实；
- 黑盒不可观测，无法校准、无法防漂移（改人格 = 重训）；
- "checkpoint/DB"混淆了两个概念：**微调权重**（静态）与**记忆检索 RAG**（动态），应当分开处理。

### 方案二：纯算法架构（冷储存 + 计算）

**描述**：采用 JSON、MD 等冷储存所有人格信息，外部环境变化时通过计算和读写来运行"人格"。纯计算的运行速度最快。

**优点**：
- 速度最快、算力成本极低、行为确定；
- 可校准、可防漂移。

**缺点 / 坑**：
- 缺理解能力；澄音本质上是 LLM 聊天桌宠，**回复生成绕不开模型**；
- 纯算法只能当"引擎"驱动模型，当不了整个"人格"。

### 方案三：算法架构 + LLM（综合型）

**描述**：借助 LLM 的理解能力将对话信息转换为可供计算的数据，再通过算法架构聚类分析写入。在算力和速度之间取平衡。

**优点**：
- 动静结合：LLM 管理解与生成，算法层管状态；
- 静态贴合与动态响应都较高。

**缺点 / 坑**：
- 若每轮对话都用 LLM 解析事件，会多一次调用，延迟与成本上升；
- 解法：**能规则就不 LLM、能批量就不实时**。

## 3. 补充方案

### 方案四：双通道 = LoRA/微调定底色 + 状态机管动态

保留方案一里"合理的部分"：用 LoRA 微调固定澄音的**语气、价值观、口头禅**（静态层），动态变量全部留在算法层。改人格只换适配器或改参数，不用重训。

### 方案五：事件溯源 + 定时离线反思（拟合度的关键）

对话不实时解析，而是**先落事件日志**；可学习状态是事件证据的可回溯摘要。每晚/每周用 LLM 做一次“反思任务”，回顾日志、提出依恋、当前自我图式或已确认策略估计的更新候选。把“学习”从在线路径挪到离线，可以降低在线成本；但慢变量不是记忆副本，能从少量记忆低成本重算的结果不重复持久化。

### 方案六：统一状态 + 按需小模型解析

- **当前与长期人格状态**：共用一份 `PersonalityState`，时间尺度只是字段的更新属性，不拆成热/温/冷三套 Schema；
- **原始互动事件**：只进互动记忆；身份事实与实体关系只进知识图谱；
- **慢变量**：只保存每轮需要稳定读取、且从完整记忆重算成本较高的低维摘要估计，并保留不透明证据引用；第一版只确定互动记忆引用，知识图谱能否作为证据后端留待 llm-wiki 架构研究；
- **解析层**：规则兜底（`emotion.py` 已有别名表）+ qwen-turbo 廉价情感/意图解析，能批量就异步跑。

## 4. 方案对比

| 方案 | 算力成本 | 运行速度 | 静态贴合 | 动态响应 | 可校准/防漂移 |
|---|---|---|---|---|---|
| 一 神经网络 | 训练云端可承担，推理+适配器有成本 | 中 | **高** | 差（黑盒） | 差（改人格=重训） |
| 二 纯算法 | 极低 | **最快** | 低（缺理解） | 高 | 最好 |
| 三 算法+LLM | 中 | 中 | 高 | 高 | 好 |
| 四 双通道（LoRA+状态机） | 训练成本中，推理低 | 中 | **高** | 高 | 好 |
| 五 事件溯源+离线反思 | 在线极低，离线定时 | 快 | 高 | **高** | 最好 |
| 六 统一状态+小模型解析 | 低 | 快 | 高 | 高 | 好 |

## 5. 推荐组合

**方案三的骨架 + 方案五的学习方式 + 方案六的统一状态与按需解析**；方案一以 LoRA 形式作为可选项叠加。

```
在线路径（快、便宜）
  事件 → 更新本轮 PersonalityState → 生成必要的人格约束 → LLM 只生成回复

解析层（按需、可异步）
  对话 → 规则兜底 + qwen-turbo 廉价解析 → 结构化事件 → 写事件日志

离线路径（定时、可云端）
  反思任务：LLM 回顾日志 → 提出慢变量更新候选 → 带 drift_protection 与用户确认
```

三个诉求各让半步：

- 在线只跑纯计算 → **快**；
- LLM 解析按需/批量 → **省**；
- 拟合度靠离线反思与事件回放 → **准**。

## 6. 可选增强：激活空间控制（Persona Vectors）

来源：Anthropic 研究《Persona Vectors: Monitoring and Controlling Character Traits in Language Models》（arXiv:2507.21509，2025-08）。在模型激活空间提取"人格向量"（evil、sycophancy、hallucination、politeness、humor、optimism 等），可**注入（steering）**与**测量（monitoring）**。

- **本质**：方案一的"进化版"——人格不焊死在权重里，而是可外置、可注入、可测量的方向数据；
- **价值**：监控 = 激活层防漂移（补参数层 drift_protection 的盲区）；控制 = 推理时 steering（比 LoRA 轻、比提示词深）；
- **前提 / 坑**：
  - 需白盒访问隐藏层激活，**仅本地 Ollama 路径可行**（论文演示模型 Qwen 2.5-7B 正是 Ollama 可跑），云端 API 拿不到激活；
  - 论文做的是稳定特质，动态状态（mood steering）未直接验证；
  - post-hoc steering 会降能力（MMLU 掉分）；效果更好的 preventive steering 需要训练期；
- **落地建议**：本地路径分两步——第一步只做**监控**（只读零风险），第二步试**轻 steering** 并 A/B 验证工具调用能力不降；云端路径退回提示词注入，保持降级；
- **结论**：不推翻推荐组合，作为本地路径的实验性增强；最值得先落的是"激活层防漂移监控"。

---

## 7. 选型结论

以**方案三（算法架构 + LLM）为骨架**落地：JSON 状态机管动态状态、LLM 管理解与生成；**离线反思 + 事件溯源**解决拟合度与成本；**分级存储 + 按需小模型解析**解决速度与算力；方案四（LoRA）与人格向量作为本地路径的可选增强。最终形态对所有运行路径（云端 API / 本地 Ollama）保持降级兼容：有激活访问就用向量，没有就退回提示词注入。
