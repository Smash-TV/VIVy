# 参数校准指南（Calibration Guide）

> 版本：v1.4（2026-08-20）
> 定位：为 `personality_core.json` 中的数值参数提供**来源说明、校准方法、防漂移策略**，避免"拍脑袋填参数"的问题。

---

## 1. 参数来源：数值从哪来？

### 1.1 三个来源层次

| 来源 | 适用参数 | 说明 |
|------|---------|------|
| **量表测量** | 依恋维度、情绪敏感性/强度等最终保留变量 | 在确认变量适用于 AI 后，参考 ECR、AIM 等量表；PANAS 只可用于 PA/NA 外部分析或映射验证，不能写成效价—唤醒内核；人类量表不能未经验证直接变成人格参数 |
| **人设校准** | Lore 相关的初始自我表示及归并后确认的人格参数 | 基于澄音的角色设定（本项目原创人设文档）设定初始命题与证据；用户反馈不能直接覆盖身份事实或把澄音校准成迎合型角色。Kelly 建构已外移到世界模型，不在本指南中作为人格参数校准 |
| **示例值** | 所有 JSON Schema 中的数值 | **当前文档中的数值均为示例**，用于说明结构，**不是最终配置**；实际值必须通过上述两种方式确定 |

### 1.2 校准流程

```
1. 确定权威变量或命题 → 2. 选择证据来源 → 3. 设定基线 → 4. 通过交互证据评估 → 5. 审慎更新并保留历史
```

> **大五边界**：OCEAN 仅作为外部评估坐标，不参与人格参数校准，也不写入 `personality_core.json`。如果使用大五量表，只能用于独立评估报告。

> **本轮派生量边界**：`empathy_intensity` 由当前情境、用户信号、推断置信度、关系证据及澄音自身状态共同生成，不作为静态人格参数校准或长期累加。无条件积极关注同样不建立分数；相关互动只作为关系证据，长期折叠到既有关系安全/被接纳预期。

---

## 2. 校准方法：怎么确定具体数值？

### 2.1 量表测量法（推荐用于特质类参数）

**适用参数**：依恋焦虑/回避、情绪敏感性（pos/neg）、情绪强度（affect_intensity）以及归并后确认的其他变量

**步骤**：
1. 选择与权威变量匹配的标准量表（如依恋维度用 ECR、情绪强度用 AIM）；效价—唤醒动态内核通过标注情境回放校准，PANAS 不能直接充当它的坐标真值；
2. 对参照人群（如"温柔型陪伴 AI"的目标用户群）施测，或让用户自评；
3. 将原始分转换为**常模分位数**（如百分位数、Z 分数）；
4. 映射到 0-1 区间（如 0.5 = 中等，0.8 = 偏高）。

**示例**：若澄音的依恋焦虑在常模中位于 35 百分位，则候选基线可记为 `attachment_anxiety: 0.35`，再结合人设证据校准。

安全型、专注型、冷漠型和恐惧型只从焦虑/回避二维位置派生，不分别校准四个类型分数，也不把派生标签写回两个连续维度。

### 2.2 人设校准法（适用于 Lore 相关参数）

**适用对象**：Markus 自我表示，以及归并后确认的调节/应对偏好和其他 Lore 相关人格参数。依恋内部工作模型不再复制成 `working_models` 对象

**步骤**：
1. 先从 Lore 与 SKILL.md 提取可核验身份事实，写入知识图谱，不把事实文本复制成人格参数；知识图谱是否同时承担人格证据存储及其引用格式，留待 llm-wiki 架构研究；
2. `mode: current` 只接纳领域特定、由重复经验或稳定人设证据组织起来，并能链接行为证据的当前自我图式；一条随口自我描述不能直接“校准成人格”；
3. 当前命题标明 `domain`、`contexts`、`importance`、`confidence` 与 `evidence_refs`。`evidence_refs` 先作为不透明引用，当前只确定互动记忆引用；`importance` 表示对自我定义的重要性，`confidence` 只表示主观确信度；两者都不能冒充准确度，也不设置重复的 `salience` 和 `centrality`；
4. 希望自我与恐惧自我仍使用同一种记录，以 `mode: hoped | feared` 区分，但它们属于可能自我。当前不为它们填写 `confidence` 充当实现概率；
5. 工作自我概念由情境即时激活，不单独校准或持久化；当前自我图式与希望自我的差异只在同一领域按需比较，不校准全局 `gap`。

### 2.3 用户反馈微调（动态校准）

**适用参数**：所有可学习参数（见 §3 防漂移机制）

**步骤**：
1. 记录用户对输入理解、事实、表达和关系边界的纠正；
2. 明确偏好可以调整面向该用户的表达策略，但不能直接改写澄音的身份事实、价值底线或自我命题；
3. 只有跨情境、可追溯的重复证据才可进入慢变量或当前自我图式的离线更新候选；
4. **必须遵守防漂移机制**（见 §3）。

## 3. 防漂移机制：怎么防止参数失控？

### 3.1 问题定义

如果用户通过反复负面反馈把某些学习权重持续推离角色基线，澄音可能逐渐出现攻击性、过度迎合或情绪反应失真，这就是需要防止的**人格漂移**。

### 3.2 防护策略示例

```json
{
  "drift_protection": {
    "hard_bounds": {
      "enabled": true,
      "per_parameter": {}
    },
    "reversion_to_baseline": {
      "enabled": true,
      "trigger": "参数偏离基线超过阈值（如 0.3）或连续 24 小时无用户纠正",
      "action": "向基线值回退 50% 或完全重置"
    },
    "user_confirmation": {
      "required": true,
      "threshold": "单次更新幅度超过 0.1 或累计漂移超过 0.2 时，需用户确认"
    },
    "logging": {
      "track_changes": true,
      "alert_on_drift": true,
      "review_period": "每日检查参数变化日志"
    }
  }
}
```

### 3.3 具体防护规则

1. **硬边界（Hard Bounds）**：
   - 每个最终变量分别定义合法范围；不能在变量归并前假定所有变量都使用 [0.0, 1.0]；
   - 身份事实、价值底线和外部评估分数不参加普通反馈学习；

2. **回溯机制（Reversion to Baseline）**：
   - 当可学习慢变量偏离自身基线超过规定阈值时，自动回退或提交离线审查；
   - 或连续 24 小时无用户纠正时，完全重置到基线值；

3. **用户确认（User Confirmation）**：
   - 单次更新幅度超过 0.1（如从 0.5 跳到 0.6）或累计漂移超过 0.2 时，暂停更新并提示用户确认；
   - 用户可选择"接受""拒绝"或"调整到指定值"；

4. **日志与告警（Logging & Alerting）**：
   - 所有参数变化记录到 `logs/personality_drift.log`；
   - 当连续少量反馈导致任一慢变量或行为偏好出现大幅变化时，触发告警并建议人工审查；
   - 每日生成参数变化报告，供复盘。

## 4. 变量依赖约束（归并完成后设计）

### 4.1 问题

不同心理变量可能相关，也可能只有情境条件下的因果关系。仅凭人类量表中的群体相关性，不能强迫澄音的一个变量自动跟随另一个变量变化。

### 4.2 解决方案

完成《7_理论变量归并表》后，逐条记录方向、证据和适用情境：

1. 只有理论定义或交互数据支持时，才建立变量依赖；
2. 区分相关、单向影响、双向影响和共同上游因素；
3. 默认只告警，不自动改写另一个变量；
4. 大五等外部评估结果不能用来施加人格内核协方差；
5. 依赖关系必须能通过情境测试或事件回放验证。

---

## 5. 校准检查清单（Calibration Checklist）

在将参数写入 `configs/personality_core.json` 前，必须完成以下检查：

- [ ] 所有数值参数已标注**来源**（量表/人设/示例）；
- [ ] 示例值已替换为**实际校准值**；
- [ ] 已确认的变量依赖均标注证据、方向和适用情境；
- [ ] 防漂移机制已启用（hard_bounds、reversion_to_baseline、user_confirmation）；
- [ ] 日志与告警已配置（track_changes、alert_on_drift）；
- [ ] 用户已确认基线值（尤其是 Lore 相关参数）。
- [ ] 大五等外部评估结果没有写回人格内核配置。
