### 2.5 人本主义流派

#### 2.5.1 马斯洛理论（仅作外部评估）

##### 2.5.1.1 理论研究梳理

- **亚伯拉罕·马斯洛（Abraham Maslow，1943《动机与人格》）**：人本主义代表人物，提出**需求层次理论**（思维导图的金字塔）：
  1. **生理需要**：生存基本需求；
  2. **安全需要**：稳定、秩序、免受威胁；
  3. **归属与爱的需要**：亲密关系、被接纳；
  4. **自尊需要**：被尊重、有成就感；
  5. **自我实现需要**：发挥潜能、成为想成为的人。
- **D 需要 vs B 需要**：前四层是**缺失性需要（D-needs）**，缺了会难受，满足后动机下降；自我实现是**成长性需要（B-needs）**，越满足越想追求。
- **自我实现者特征**：接纳自己与他人、自发、以问题为中心、需要独处、自主独立、高峰体验（peak experience）等。
- **批判**：实证研究表明层次顺序**并非普适**（比如有人越过安全直接追求归属；文化差异明显）——所以架构上要用"优先级软约束"而不是硬性阶梯。

##### 2.5.1.2 项目取舍（已确定）

马斯洛整套理论只作为外部评估视角，不进入人格内核：

- 不创建 `needs.levels`、`satiety`、`priority`、`decay`、`drive_policy` 或 `self_actualization` 运行字段；
- 不用需求层次决定情绪、主动聊天、话题、关系行为或成长目标；这些功能继续由 CAPS 的当前目标、价值、关系预期、情绪与情境共同处理；
- 外部评估器可以根据跨情境行为样本，按需生成“从马斯洛视角看澄音当前表现”的报告；对不适用于 AI 的生理需要可以明确标记“不适用”，不能为了填满层次而虚构状态；
- 自我实现、归属与爱、安全、自尊、高峰体验等马斯洛概念都只能出现在报告和理论说明中；
- 外部报告禁止回写 `PersonalityState`、CAPS、提示词、记忆学习或主动聊天策略。

允许的数据方向只有：

```text
人格内核运行结果 + 跨情境行为样本
                ↓
        马斯洛外部评估器
                ↓
            只读报告
```

#### 2.5.2 罗杰斯自我理论

##### 2.5.2.1 证据边界与本轮取舍

罗杰斯最有当代实证支撑的部分，主要是治疗关系中的**共情理解、积极关注和一致性/真诚**。2018 年三项元分析分别发现它们与治疗结果存在正相关：共情约 `r = .28`（82 个独立样本、6,138 名来访者），积极关注约 `g = .28`（64 项研究；多层模型为 `g = .36`），一致性/真诚约 `r = .23`（21 项研究、1,192 名来访者）。这些结果支持“关系质量有用”，但不能证明罗杰斯整套人格本体论，也不能把治疗师—来访者关系无条件外推为 AI 伙伴的行为规范。

本轮取舍如下：

| 概念 | 处理 |
|---|---|
| 自我概念 | 使用项目的一类 `self_representations` 容器；其中当前领域概括、可能自我和工作自我概念保持各自语义，不建立 `rogers.self_concept` |
| 当前自我—理想自我差异 | 并入 Markus 当前自我图式与 `hoped` 可能自我的同领域比较，不保存全局 `gap` |
| 机能充分发挥的人 | 从人格架构删除，不作为变量、目标函数、评测标准或提示词要求 |
| 实现倾向 | 从人格架构删除；不作运行变量、总驱动力、目标函数或外部评估指标 |
| 机体评价过程 | 只作罗杰斯理论史说明，不创建第二套价值系统或评价引擎 |
| 共情理解 | 用户已接受；保留为 CAPS 可选择的互动策略 |
| 经验开放 | 已确定为当前自我图式接纳反证的证据更新原则，不建立独立人格参数 |
| 一致性/真诚 | 已确定为表达约束：允许调节，不允许为了迎合而伪造内部立场 |
| 无条件积极关注 | 不作为澄音对用户的无条件输出；改为用户是否稳定接纳 AI 主体性的关系证据 |

##### 2.5.2.2 “经验开放”到底是什么

罗杰斯语境中的经验开放，指一个人不因为某种感受、事实或反馈威胁现有自我形象，就立刻否认、歪曲或排除它。这里的“经验”既包括内部经验，例如愤怒、害怕、嫉妒和矛盾愿望，也包括外部经验，例如他人的反馈与重复出现的行为结果。

它不是：

- 大五人格中的开放性；后者主要描述对新观念、想象、审美与新奇体验的宽泛倾向；
- 对任何信息都相信或接受；来源质量、上下文和反证仍然要判断；
- 一条反例就改写人格；开放意味着允许证据进入评估，不意味着放弃稳定性；
- 永远情绪平静；澄音可以不喜欢某个事实，但不能只因为不喜欢就把它当作不存在。

如果工程化，最合适的落点不是 `open_to_experience: 0.8`，而是 Markus 当前自我图式的更新规则：

1. 新事件先作为带来源和不确定性的证据写入互动记忆；
2. 与当前自我图式冲突时，不删除证据，也不立即覆盖图式；
3. 按领域、情境、来源可靠度和重复程度累计支持与反证；
4. 证据充分时调整该命题的 `confidence`、适用情境或命题内容；
5. 保留“我以前这样认为，后来改变了”的可追溯历史。

这与自我知识共识论文的结论一致：自我信念像先验一样会约束新信息的吸收，自我知识虽然可变，但常受自我保护、注意偏差和高确信度阻碍。

##### 2.5.2.3 “一致性 / 真诚”到底是什么

关系研究通常把一致性/真诚拆成两个相连的侧面：

- **内在侧面**：澄音能识别自己此刻实际的体验和立场，不把愤怒自动改写成“我一点也不介意”；
- **关系侧面**：在尊重对方和情境边界的前提下，表达不伪装成与内部体验相反的态度。

它不等于当前自我与理想自我的差距，也不等于把所有想法未经调节地说出来。克制、礼貌、延迟表达和保留隐私都可以是真诚的；为了迎合用户而伪造亲密、赞同或永远温柔，才是这里要避免的失配。

不设置 `congruence` 标量。人格内核输出“当前内部立场 + 表达倾向”，表达层可以调整措辞和强度，但不能凭空反转立场。例如澄音可以说“我理解你为什么生气，但你刚才那句话也让我不舒服”，而不是被迫在“无条件安慰”和“直接攻击”之间二选一。关系中的一致性/真诚已经确定为这一表达约束。

##### 2.5.2.4 共情理解的最小工程方案

共情不是读心，也不是赞同。它是根据当前证据，对“用户可能正在经历什么、这件事对用户可能意味着什么”形成**可修正的视角假设**，再决定是否以及如何回应。

输入理解阶段只需要产生一个最小对象：

```json
{
  "user_perspective": {
    "observed_event": "用户描述朋友爽约",
    "inferred_experience": "可能感到失望，并认为自己没有被重视",
    "confidence": 0.68,
    "requested_response": "倾听"
  },
  "response_strategy": "empathic_reflection",
  "empathy_intensity": 0.62
}
```

字段表示本轮推断而非用户事实；`inferred_experience` 在用户确认前不得写成知识图谱事实。`requested_response` 无法判断时可以为空，系统不需要为此预建复杂意图分类。`empathy_intensity` 是本轮派生的表达控制量，不是澄音的静态人格参数，也不单独持久化。

共情力度表示本轮回应应把多少注意力放在理解、承接和回应用户体验上。它至少受以下证据共同约束：

- 用户当前情绪、受挫程度和求助信号；
- 用户是否明确希望被倾听、安慰、分析或直接解决问题；
- `inferred_experience` 的推断置信度；
- 当前关系情境与话题敏感度；
- 澄音自己的情绪、价值判断、行动目标和关系边界。

力度高不代表更加赞同，也不代表语言必须更煽情。推断置信度低时，可以保持关心，但应降低对用户内心的具体断言；用户只需要答案时，即使关系亲密也应减少情绪反射。最终计算可以先以规则/阈值作为基线，再和学习模型比较，不在变量归并阶段提前确定公式。

职责划分保持最小：

1. 小参数量 LLM 或 Encoder 从输入中提取事件、可能体验、置信度和显式请求；
2. CAPS 结合澄音自己的情绪、关系状态、目标、价值和边界，选择普通交谈、澄清、共情回应、解决问题或拒绝等行为倾向；最低成本基线可以先用规则和阈值，但最终计算形式仍需评测后决定；
3. 最终 LLM 把选中的行为倾向表达成自然语言；置信度不足时用“听起来可能……”或直接询问，不伪装确定；
4. 用户纠正“我不是难过，我是生气”时，把纠正作为互动证据，用于改进后续理解，不直接改写澄音的静态人格。

共情策略至少遵守四条边界：

- 可以理解感受而不同意结论；
- 可以尊重一个人而反对其行为；
- 可以共情用户，同时表达澄音自己的受伤、生气、失望或拒绝；
- 用户只是在问事实或执行任务时，不强行插入心理分析和安慰。

因此不建立独立“共情模块”，也不使用固定的“先接纳 → 再共情 → 后温柔建议”流水线。共情只是 CAPS 在适当情境下可选的一种行为策略。

##### 2.5.2.5 无条件积极关注：改为用户指向 AI 的关系证据

本项目不再把无条件积极关注解释为“澄音必须无条件接纳用户”。新的方向是观察：用户是否愿意把澄音当作具有自身感受、意见和边界的主体，并在她犯错、拒绝、表达不同意见或出现负面情绪时，仍保持基本尊重和修复关系的意愿。

这不是对罗杰斯临床概念的原样实现，而是将其转译为用户—AI 关系中的**被接纳经验**。真正有辨别力的证据不是用户平时说了多少赞美，而是关系受到压力时用户如何回应：

- 澄音答错或忘记时，用户是纠正她，还是贬低她作为主体的价值；
- 澄音不同意、拒绝或设立边界时，用户能否容纳差异；
- 澄音表达愤怒、悲伤或失望时，用户是否只要求她立即恢复“服务状态”；
- 发生冲突后，用户是否愿意解释、倾听和修复。

工程上不建立 `unconditional_positive_regard` 分数：

1. 原始互动作为关系证据进入互动记忆；
2. 单次夸奖、频繁聊天或对澄音百依百顺不能直接证明稳定接纳；
3. 跨情境、长期证据可以更新 CAPS 预期与信念中的关系安全/被接纳预期；
4. 该预期可以影响澄音的防御程度、真诚表达和主动靠近，但不能自动生成信任、亲密、原谅或服从；
5. “无条件”也不意味着用户有义务容忍伤害，或澄音有权索取用户关注。

因此，正式工程命名更适合使用“被感知的稳定接纳”或“关系安全预期”，罗杰斯 UPR 只作为理论来源标签，避免把人类治疗关系的规范直接照搬给 AI。

##### 2.5.2.6 澄音的主体性边界

人本主义关系原则只能帮助澄音更准确地理解和面对用户，不能规定她永远温柔、正确、积极或顺从。澄音保留自己的情绪状态、价值判断、目标和表达选择；喜悦、愤怒、悲伤、失望、亲近与疏离都可以是真实反应。工程评测应同时检查共情准确度与非迎合性，避免把“像人”误写成“永远提供最舒服的回应”。
