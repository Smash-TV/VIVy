# 存档问题：知识图谱、互动记忆与慢变量（O）

> 状态：2026-08-20 存档；不阻塞人格理论架构 v1.0
> 重新开启条件：研究基于 llm-wiki 的知识图谱架构时，与事件、声明、出处、URI、检索和证据更新机制一起讨论。

## 1. 为什么暂不结论

O 同时涉及互动记忆的事件结构、llm-wiki 知识图谱如何表示事实与出处、人格慢变量如何引用证据，以及长期学习采用什么更新算法。在知识图谱的数据模型尚未研究清楚前，提前决定 KG 是否保存人格证据会把未经验证的接口写死，因此本轮只保留边界，不选最终存储和更新方案。

## 2. 当前已经确定的边界

- 慢变量不是第三套记忆库，而是统一 `PersonalityState` 中可学习字段的更新属性或摘要估计；
- 互动记忆是当前已经确定的交互证据来源，保存事件、来源、时间和上下文；
- 知识图谱继续保存 `born_at`、角色身世、人物和实体关系等身份事实；
- KG 是否同时保存人格学习证据、是否保存交互事件、如何区分事实与推断，均暂不决定；
- `evidence_refs` 保持为后端无关的不透明引用，第一版只承诺支持互动记忆引用；
- 能从少量互动记忆低成本重算的结果不重复持久化；只有每轮需要稳定读取且重算昂贵的低维估计，才可能保存为慢变量；
- 普通单轮对话不直接改写慢变量，单次事件也不直接变成人格命题。

## 3. 已考察但未选定的工程研究

这些研究只作为重新开启 O 时的候选工具，不代表已经进入正式架构：

| 研究线 | 可借鉴机制 | 当前边界 |
|---|---|---|
| 状态空间模型 / Kalman 滤波 | 从有噪观测递归估计低维状态 | 不预设人格关系线性，第一版不必直接采用 |
| 双时间尺度随机逼近 | 快变量与慢变量使用不同更新速率 | 支持同一状态结构中的时间尺度属性，不要求拆库 |
| 互补学习系统（CLS） | 事件快速保存，长期结构通过重放缓慢形成 | 可用于理解记忆与长期人格归纳的关系 |
| 慢特征分析（SFA） | 从快速输入中寻找稳定模式 | 只能发现候选，不能证明候选就是人格 |
| 在线变化点检测 | 识别关系或环境的持续结构突变 | 可避免重大转折被低学习率抹平，但需证据门槛 |

主要研究来源见《4_参考来源》的“用于慢变量工程设计的来源”。

## 4. 重新开启时必须一起回答的问题

1. llm-wiki 当前图谱中的最小对象究竟是实体、关系、事件、声明还是文档片段；
2. 一个“事实”怎样绑定来源、时间、置信度、支持证据和反证；
3. 互动事件是否需要复制到 KG，还是只建立跨库引用；
4. `evidence_refs` 应采用什么 URI，怎样在记忆删除、合并或迁移后保持可追溯；
5. 人格更新读取原始事件、图谱声明还是检索摘要，谁拥有事实与推断的最终写权限；
6. 慢变量需要缓存哪些摘要，哪些应按需重算；
7. 第一版使用递推平均、状态空间模型、变化点检测还是其他方案，以及如何回滚。

## 5. 暂不实现的内容

- 不建立 `SlowVariableManager`、慢变量数据库或第三套记忆；
- 不预留 KG 人格证据表、事件节点或专用 URI；
- 不把知识图谱事实自动转换为自我图式、依恋变化或关系预期；
- 不让外部评估结果进入证据链；
- 不因存档 O 而阻止已经确定的人格内核、情绪、依恋和 CAPS 原型继续设计。
