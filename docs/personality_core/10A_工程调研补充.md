# 工程调研补充：感知后端、确定性回放与事件顺序

> 日期：2026.8.21  
> 配套文档：`10_工程实现调研与落地主线.md`  
> 阅读范围：只在实现阶段 0（契约/回放）或阶段 4（慢学习）时需要；不改变主文档的主线和 7/8/9 的理论边界

## 1. 三个现有模型后端不能共用同一个“结构化输出保证”

应维护一个很小的 provider/model capability 表，而不是假定所有后端都支持严格 JSON Schema。

| 后端 | 官方能力 | 处理方式 |
|---|---|---|
| Ollama | 可在 `format` 中传 JSON Schema | 优先 schema constrained output，低温度，返回后再做业务校验；[官方文档](https://docs.ollama.com/capabilities/structured-outputs) |
| 阿里云百炼 / Qwen | JSON Object 普遍可用，严格 JSON Schema 只覆盖部分型号 | 按具体 model 登记能力；[官方文档](https://help.aliyun.com/en/model-studio/qwen-structured-output) |
| DeepSeek | JSON mode 保证合法 JSON，但官方提示可能截断或返回空内容 | 检查 `finish_reason`、空内容和完整字段，有限重试后 `abstain`；[官方文档](https://api-docs.deepseek.com/guides/json_mode/) |

两层验证缺一不可：

1. 解码层检查 JSON/schema 形状；
2. 业务层检查值域、枚举、原文 evidence span、字段间约束、事件幂等和写入权限。

格式正确不表示语义正确。LLM 自报的 confidence 也不能直接作为可靠度；先允许 `abstain`，再在人工标注集上用 ECE、Brier、NLL 和 risk–coverage 选择各字段门槛。[Guo 等，2017](https://proceedings.mlr.press/v70/guo17a.html)

有了足够稳定的人类标签以后，高频封闭字段才值得训练一个校准 encoder，让小 LLM 只处理含糊语义。少样本基线可参考 [SetFit](https://arxiv.org/abs/2209.11055/)。v0 没有数据时先不要增加一个未经校准的分类器。

## 2. 回放时绝不能重新调用 LLM

感知或证据抽取结果必须作为带来源的派生事件固定保存，至少包含：

```text
input_event_refs[]
structured_observations
evidence_spans[]
provider / model
prompt_hash
schema_version
rule_or_encoder_version
created_at
status
```

状态重放读取已经保存的标注。若回放时重新调用 LLM，同一段历史会随着模型、prompt 或采样变化产生另一套“过去”，审计和 rollback 就失去意义。需要升级抽取器时，对冻结的原始事件跑 shadow re-annotation，比较后创建新的 annotation revision，不能覆盖旧结果。

【2026.8.22 落地说明】新修订已把完整 `PerceptState`、`elapsed_seconds` 与配置快照写入 `state_revisions`，回放按 `applied_sequence` 读取冻结值；旧 v0 修订缺少这些字段时会明确标为不可验证，不再调用当前 `perceive()` 重写过去。

## 3. UUID 负责引用，流内序号负责顺序

`urn:uuid:<uuid4>` 继续作为 v0 稳定证据 ID；项目最低 Python 版本无需为 UUIDv7 另加依赖。即使以后使用 UUIDv7，它也只提供大致时间排序，不能代替严格重放顺序。

建议给 `InteractionEvent` 补充：

```text
source_id
stream_id
stream_seq
occurred_at
recorded_at
causation_ref?
supersedes_ref?
status: active | invalidated | redacted
```

并设置：

```text
UNIQUE(source_id, event_id)
UNIQUE(stream_id, stream_seq)
```

信封语义可借 [CloudEvents 1.0.2](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md)，无需引入其 SDK。`occurred_at` 是事情发生时间，`recorded_at` 是系统得知时间，`stream_seq` 是系统内确定重放顺序。

## 4. 数值型慢变量只在门槛后做有界批量提案

若阶段 4 选择了一个真正连续、结果可观察的关系性预期，可先使用：

```text
batch_value = weighted_mean(qualified_evidence)
gain = min(gain_max, batch_weight / (prior_strength + batch_weight))
delta = clip(gain * (batch_value - old_value), -max_step, max_step)
proposed_value = clip(old_value + delta, field_bounds)
```

同一长会话要限制总权重；跨日期、跨会话、跨情境的重复证据才增加多样性。门槛、`gain_max` 和 `max_step` 都是 Gwen 的工程安全参数，不是心理学常数。真正二元且结果近似可交换的预期才考虑 Beta-Binomial；LLM 连续评分不能伪装成伯努利观测。

依恋、自我表征、EAS、价值和连接权重不套这个公式；它们继续只形成带证据的人工审核提案。

## 5. 两个实现期补充检查

1. 若原始事件和人格状态位于不同 SQLite 文件，原始事件是权威，状态是幂等投影。事件已提交但投影失败时按 `event_id` 重试，不要假装两库天然具有同一事务。
2. 状态序列测试可用 [Hypothesis `RuleBasedStateMachine`](https://hypothesis.readthedocs.io/en/latest/stateful.html) 随机生成事件，并逐步检查边界、幂等、`abstain` 不写入、模型超时保持旧状态和重放一致性。它会自动缩减最短反例；v0 不需要先上 TLA+。

多轮角色评测还可参考：

- [EmoCharacter](https://aclanthology.org/2025.naacl-long.316/) 的情绪轨迹和转移方法，但只能映射到已冻结的二维效价—唤醒；
- [MultiChallenge](https://aclanthology.org/2025.findings-acl.958/) 的 instruction retention、跨轮推断记忆、自洽和版本编辑压力测试。
